# SPEC-105 — Per-row AI verdict column on the Catalog table (on-demand, visible-only)

## Context / Why

Backend SPEC-103 adds `GET /analysis/products/catalog-verdicts?ids=…` — per-product AI
verdicts generated on-demand for a passed-in set of product IDs, cached server-side. This
spec surfaces them as a new **"AI verdict"** column on the Catalog table, generated **only
for the currently-visible page of products**, with the table rendering instantly and only
the verdict cell showing a skeleton until its note arrives.

## Scope (Catalog tab only — `/products/catalog`)

- Add **client-side pagination** to the catalog table (10 rows/page) — `CatalogView` is
  already `"use client"` and already holds all rows, so this is local state, no refetch.
- Add an **"AI verdict"** column to `CatalogTable` and the equivalent field to
  `CatalogGrid`, rendering: the verdict text, or a **skeleton** while it's loading, or
  `—` once fetched but empty.
- On mount and whenever the visible page changes, fetch verdicts for **only the visible
  product IDs** via `/api/proxy/analysis/products/catalog-verdicts?ids=…`, merging results
  into a client verdict map. Mirror the existing on-demand idiom
  (`ai-commentary.tsx` / `markdown-plan-page.tsx`: `useState` + `useEffect` +
  `cancelled` guard + `fetch("/api/proxy/…")`). No SWR/react-query (repo has none).
- **Initial paint from cache:** the Catalog RSC (`product-page-content.tsx`) pre-fetches
  the first page's cached verdicts with `cache_only=true` (server-side `serverApi`) and
  passes them as `initialVerdicts`, so already-cached notes appear with no skeleton flash;
  only uncached ones show a skeleton and are generated by the client fetch.

## Types (`types/analysis.ts`)

```ts
export interface CatalogVerdict { product_id: number; verdict: string }
export interface CatalogVerdicts {
  verdicts: CatalogVerdict[];
  generated_at: string;
  stale: boolean;
}
```

## Data / services (`services/analysis.ts`)

`getCatalogVerdicts(query, ids, { cacheOnly })` → `serverApi<CatalogVerdicts>(
"/analysis/products/catalog-verdicts?…&ids=…&cache_only=…")` — used server-side for the
`initialVerdicts` cache_only pre-fetch. The client-side per-page fetch calls
`/api/proxy/analysis/products/catalog-verdicts?…` directly (browser `fetch`), same as the
other on-demand components.

## Component behaviour (`catalog-view.tsx`)

- `page` state (`useState(1)`), `PAGE_SIZE = 10`, `visible = rows.slice(...)`,
  `visibleIds = visible.map(r => r.product_id)`.
- `verdicts: Map<number, string>` seeded from `initialVerdicts`; `fetchedIds: Set<number>`
  tracks which ids the client has resolved (so an empty result shows `—`, not an endless
  skeleton).
- `useEffect` keyed on `visibleIds.join(",")`: fetch verdicts for visible ids not already
  known; merge into the map; mark ids fetched. `cancelled` cleanup guard.
- Pass `visible` rows + a `verdictState` (map + fetchedIds) into `CatalogTable`/`CatalogGrid`
  and render pagination controls (Prev / "Page X of N" / Next), tokens only.

## Cell rendering (`catalog-table.tsx`, `catalog-grid.tsx`)

New "AI verdict" column/field per row:
- `verdicts.has(id)` → the text.
- else `fetchedIds.has(id)` → `—` (muted).
- else → `<Skeleton className="h-4 w-40" />` (the pulse is the one allowed animation).

## Pure logic (`lib/catalog-pagination.ts`) + tests

Extract `paginate(rows, page, size)`, `pageCount(total, size)`, `visibleIds(rows)` as pure
functions unit-tested in `tests/catalog-pagination.test.ts` (node env — no jsdom). The
component itself is verified via the manual checklist below.

## Design compliance (Rule 9)

- Semantic tokens only (`text-muted-foreground`, `bg-muted` via `<Skeleton>`,
  `border-border`) — no hex, no `text-*-500`.
- **No Framer Motion, no entrance animations.** The table renders instantly in final
  position; the only motion is the skeleton pulse (explicitly allowed) and existing
  hover/focus transitions.
- shadcn `<Skeleton>`; 8px spacing; keyboard-navigable pagination buttons; responsive.
