# SPEC-022 — Daily Reports Page

- **Status:** Implemented
- **Date:** 2026-07-16
- **Backend:** existing `GET /reports` (paged list) + `GET /reports/{date}`
  (Markdown + metrics); reports are stored per-date in the DB (SPEC-009) and
  the content follows the client's v2 section list (backend SPEC-016).
- **Value orientation (owner decision):** a morning briefing, not a table —
  verdict-first AI-written narrative with the full history browsable.

## Changes

1. Nav: "Reports" item (`/reports`, FileText icon) in `lib/navigation.ts`.
2. `services/reports.ts` — `listReports()`, `getReport(date)` via `serverApi`;
   types in `types/reports.ts`.
3. `app/(app)/reports/page.tsx` (RSC) — `?date=` selects a report (default:
   newest). Layout: archive rail (report dates, newest first, active
   highlighted) + the selected report rendered as Markdown.
4. `features/reports/report-archive.tsx` — date list with links;
   `features/reports/report-viewer.tsx` — Markdown rendering reusing the
   chat's `ChatMarkdown` component (same token-styled renderer), plus a
   "generated by AI / fallback" badge and generated-at line.
5. Empty state: no reports yet → explains the 06:00 UTC daily job and that
   history accumulates automatically.

## Acceptance criteria

- [x] Archive lists every stored report, newest first.
- [x] All four frontend gates green.
